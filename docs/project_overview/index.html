01Project introduction

A research workspace you can audit.

ResearchCompass is built for literature review and evidence management, not for generating confident-sounding prose. Papers become a private, section-aware library; searches return evidence with page and chunk locations; syntheses are accepted only when their claims resolve to verified evidence; projects keep the whole trail structured.

Evidence first

Search returns paper, section, original passage and four retrieval scores. A claim without a verified chunk_id is not presented as a supported conclusion.

traceablepage-aware

One workspace

Library, smart search, evidence synthesis, paper analysis, citation graph, research projects and report export share the same evidence base and permission model.

unifiedproject-scoped

Built to be audited

Failures are explicit: strict graph mode does not silently degrade, unsupported statements are listed separately, and deterministic progress replaces hand-waved status.

explicit failurereproducible
What it is not.It is not a paper generator, not a black-box summarizer, and not a replacement for domain judgment. It is the evidence layer around your own reasoning.

03Core method

From paper pile to defensible evidence.

The method is deliberately narrow: make the corpus structurally readable, retrieve passages rather than vibes, validate every claim against the snapshot, and keep the work trail in a project.

01

Academic chunking

Parse PDFs and split by Abstract, Introduction, Method, Experiments and Conclusion while preserving page numbers and character ranges.

Academic Paperpage-aware
02

Hybrid retrieval

Rewrite the query, combine vector and BM25 recall with RRF, rerank candidates, then aggregate evidence into paper cards with four scores.

local_hybridRRFrerank
03

Evidence-constrained synthesis

Generate themes, claims, contradictions, limitations and gaps from the retrieval snapshot; reject citations that do not resolve to verified chunks.

evidence_chunk_idsunsupported_claims
04

Project execution

Collect results as project assets, link them to milestones and tasks, compute progress from tasks, and export a report without copying the underlying sources.

milestonesassetsreports
Evidence contractenforced in synthesis
claim.evidence_chunk_ids

Every supported claim carries chunk identifiers from the retrieval snapshot.

verified_snapshot

Citations must resolve to a real chunk_id; missing evidence fails validation.

unsupported_claims

Statements the model cannot support are emitted separately, never disguised as conclusions.

strict_hybrid_citation_graph

If the graph is not ready, strict mode fails explicitly instead of silently falling back.

06Quick start

Run the full stack in four steps.

Docker Compose is the supported development path. The full stack starts PostgreSQL, Redis, MinIO, Milvus, Neo4j, the API, the worker and the web app.

01

Clone

git clone --branch v0.11.15 --depth 1 https://github.com/LPK3215/ResearchCompass.gitcd ResearchCompass
02

Initialize

# Linux / macOS./scripts/init.sh# Windows PowerShell.\\scripts\\init.ps1
03

Start

docker compose up -d --build

Web localhost:5173 · API health localhost:5051/api/system/health

04

Verify

make lintmake testmake test-web

Full cold-build gate: .\\scripts\\release_check.ps1

Lite mode

No knowledge base, graph or research dependencies: make up-lite starts the core services and defaults to /agent.

Production

cp .env.prod.template .env.prod, fill required values, then docker compose -f docker-compose.prod.yml up -d --build.

Evaluation

make eval-baseline KB_ID=kb_xxx, make eval-ablation KB_ID=kb_xxx, make eval-synthesis KB_ID=kb_xxx.

08API surface

Two calls cover the evidence path.

The research API is exposed under /api/research. Search is synchronous; synthesis creates a run and returns immediately, then the client polls the run. Both require an authenticated user.

curl -sS -X POST "$API/api/research/databases/$KB/search" \  -H "Authorization: Bearer $TOKEN" \  -H "Content-Type: application/json" \  -d '{    "query": "What are the common limits of evidence aggregation for RAG in academic literature?",    "retrieval_mode": "local_hybrid",    "top_k": 8,    "recall_top_k": 50,    "year_from": 2020,    "year_to": 2026  }'

Response fields

{  "run_id": "[run-id]",  "rewritten_query": "[rewritten query]",  "keywords": ["[keyword]"],  "items": [{    "paper_id": "[paper-id]",    "title": "[paper title]",    "evidence": [{      "chunk_id": "[chunk-id]",      "section_title": "[section]",      "scores": { "vector": "[score]", "bm25": "[score]", "hybrid": "[score]", "rerank": "[score]" }    }]  }],  "stage_timings": { "query_rewrite_ms": "[ms]", "retrieval_ms": "[ms]", "aggregation_ms": "[ms]" }}
curl -sS -X POST "$API/api/research/databases/$KB/syntheses" \  -H "Authorization: Bearer $TOKEN" \  -H "Content-Type: application/json" \  -d '{    "query": "What are the common limits of evidence aggregation for RAG in academic literature?",    "top_k": 8,    "recall_top_k": 50  }'

Run, then poll

# immediate response{ "run_id": "[run-id]", "task_id": "[task-id]", "status": "pending" }# poll until terminalcurl -sS "$API/api/research/synthesis-runs/$RUN_ID" \  -H "Authorization: Bearer $TOKEN"
Synthesis is evidence-bound.The run fails with synthesis_insufficient_evidence if the snapshot has fewer than two papers with evidence, and validation requires every cited chunk_id to resolve.

11Contributing

Keep the evidence path intact.

One PR should solve one clear problem. Large changes start with an issue; UI changes include a screenshot or recording; user-visible changes update the docs and changelog.

01

Fork & branch

Use a semantic branch name such as feature/evidence-filter or fix/graph-sync.

02

Run the checks

make formatmake lintmake test
03

Open a PR

Describe what changed, why, the affected scope and how it was verified. Use the PR template.
