# 从选题到成稿：一条可追溯的科研流水线

这篇文档解决一个具体问题：**打开 ResearchCompass 之后，按什么顺序点、每一步产出什么、最后怎么变成论文里的文字。**

一句话原则：先把"证据账本"建起来，再动笔；每写一句都能指回原文，写作才不会返工。

## 全局：七步流水线

| 步骤 | 你在做什么 | 系统入口 | 这一步的产出 |
| --- | --- | --- | --- |
| 0 | 准备知识库与模型 | 知识与工具管理 → 知识库 | 一个可检索的文献库 |
| 1 | 锁定选题与文献集 | 论文库 / 研究趋势 / 研究机会 / 导入公开论文 | 20～50 篇核心论文 |
| 2 | 把文献读薄 | 论文分析（单 Agent / 多 Agent） | 每篇的结构化摘要 |
| 3 | 建立证据账本 | 智能检索（本地混合 / 严格图谱） | 可复查的证据片段 |
| 4 | 写文献综述 | 证据综述（证据校验 → 生成） | 带引用绑定的结构化综述 |
| 5 | 推进课题 | 研究项目（里程碑 / 任务 / 成果 / 风险） | 项目计划与进度 |
| 6 | 变成论文文字 | 综述导出 / BibTeX 导出 / AI 研究助手 | 各章节草稿与参考文献 |
| 7 | 自证严谨 | RAG 评估 / 消融实验 / 分析对比 / 用户评测 | 可复现的实验与评测证据 |

下面按顺序展开。每一步都给出**点哪里**和**怎么判断做对了**。

## 第 0 步：准备（10 分钟）

1. 登录后进入「知识与工具管理 → 知识库」，新建一个 Milvus 知识库，嵌入模型选本地 `local-embedding`（默认已启用）。
2. 进入知识库详情 →「文件管理 → 上传」，把论文 PDF 拖进去。解析时选择 **Academic Paper** 分块策略，系统会按摘要、引言、方法、实验、结论分块，并保留页码与字符区间。
3. 等状态变成「已入库」。

**做对了的标志**：知识库详情的统计里能看到 chunk 数与 token 数（例如 11 篇 PDF ≈ 336 chunks）。

> 想加公开论文：科研罗盘顶部「导入公开论文」，输入标题或 DOI，系统通过 Semantic Scholar 拉元数据与 PDF。大批量导入建议先在 `.env` 配好 `SEMANTIC_SCHOLAR_API_KEY`。

## 第 1 步：锁定选题与文献集

选题不是拍脑袋，先看三张图：

| 想看什么 | 入口 | 怎么用 |
| --- | --- | --- |
| 这个领域近几年怎么变 | 科研罗盘 → 研究趋势 | 看发表年份柱状图、高频关键词、关键词演进；判断哪条线在升温 |
| 哪里还有空白 | 科研罗盘 → 研究机会 | 看机会分（增长 + 近期性 + 覆盖度 + 图谱缺口）和"判断依据"，挑 1～2 个方向 |
| 谁在引用谁 | 科研罗盘 → 引用图谱 | 先点「同步引用图谱」，再找枢纽论文与两跳关系 |

把选题收敛成一句可检索的问题，例如：**"RAG 在学术文献场景中的证据聚合方法有哪些共同局限？"** —— 后面所有检索、综述都围绕这一句。

**做对了的标志**：你能说出"我这篇要回答的一个问题"和"支撑它的 3～5 篇关键论文"。

## 第 2 步：把文献读薄

两种读法，按需要选：

| 方式 | 入口 | 适合 |
| --- | --- | --- |
| 单篇结构化提取 | 论文库 → 点标题 → 论文分析 | 快速抓研究问题、方法、数据集、结果、局限 |
| 四阶段多 Agent 分析 | 同上，选多 Agent 模式 | 需要创新点、方法学与研究空白的系统拆解（约 30 秒） |

读完一批之后，你手上应该有一张"论文 → 一句话贡献 → 一句话局限"的表。

**做对了的标志**：每篇论文你都能说出"它解决什么、用什么方法、在什么数据上、没解决什么"。

## 第 3 步：建立证据账本（最关键的一步）

入口：科研罗盘 → 智能检索。

1. 选检索模式：
   - **本地混合**：向量 + BM25 + 重排，稳定、可追溯，适合绝大多数写作场景。
   - **严格图谱**：在本地混合之上叠加论文引用图谱与 PPR 扩展，适合做引用网络分析；**图谱没同步会直接失败**，不会偷偷降级。
2. 填研究问题，设置年份区间、返回论文数、候选证据数，点「开始检索」。
3. 看结果：每条证据包含论文标题、章节、原文片段、字符区间，以及 bm25 / vector / hybrid / rerank 四路分数。
4. 把重要的检索「置顶」，之后可以按原配置重跑。

**做对了的标志**：你能用一句话复述结论，并且 3 秒内点开它对应的原文段落。

## 第 4 步：写文献综述（系统帮你写"有证据的那部分"）

入口：科研罗盘 → 证据综述。

1. 可以直接从检索结果点「生成证据综述」，问题与筛选条件会带过去。
2. 生成过程：查询改写 → 本地混合检索 → 结构化综述 → 证据校验 → 生成。
3. 如果提示 **"综述只能引用已验证证据"**：页面会出现「证据校验」面板，点「一键录入并验证」（或逐条验证），再点「重新生成」。
4. 成功后会得到：主题综述分组、核心结论（带置信度与绑定论文）、证据矛盾、研究局限、研究空白，以及**未支持结论**（模型想说但没有证据的句子，会被单独列出来——这部分正是你写作时要自己补文献的地方）。
5. 点「Markdown / DOCX」导出。

> 这一步的本质：让系统把"能证明的"整理好，把"不能证明的"标红给你。

## 第 5 步：推进课题（可选，但强烈建议）

写作是长期工程，用它管住进度：

1. 科研罗盘 → 研究项目 →「新建项目」，写清项目名与研究问题。
2. 建 3～5 个里程碑（如：文献调研 / 方法确定 / 实验完成 / 初稿 / 定稿），每个里程碑下拆任务，设截止日期与优先级。
3. 把第 2～4 步的成果「归集」到项目（论文、检索、综述、分析、实验），并关联到具体任务上——这就是你的证据链。
4. 有卡点时登记「风险登记」，避免遗忘。
5. 随时「导出报告」（Markdown / Word / CSV），直接用于组会或交给导师。

**做对了的标志**：项目详情里，每个里程碑都能看到它依赖的成果；进度是任务自动算出来的，不是手填的。

## 第 6 步：把素材变成论文文字

系统产出的是**素材**，论文仍要你自己写。下面是经过验证的映射关系和可复制的提示词。

### 6.1 论文结构 → 平台产出

| 论文章节 | 用哪份产出 | 操作 |
| --- | --- | --- |
| Introduction / 研究背景 | 研究趋势 + 研究机会 | 导出趋势结论，用"近 N 年 X 篇、关键字演进"支撑背景 |
| Related Work | 证据综述的"主题综述"与核心结论 | 导出 Markdown，按主题重组段落 |
| Method / 方法对比 | 论文分析 + 分析对比 | 用多 Agent 报告的方法学部分做对比表 |
| Results / 讨论 | 证据综述的"核心结论" | 每条结论后面挂 `[论文标题 · 章节]` |
| Limitations | 证据综述的"研究局限"与"证据矛盾" | 直接改写，保留原文依据 |
| Future Work | 证据综述的"研究空白" | 每条配一句"为什么现在还没解决" |
| 参考文献 | 论文库导出 | 导出 BibTeX / RIS，导入 Zotero / EndNote |

### 6.2 四个可直接复制的提示词（发给 AI 研究助手）

> **对比表**
> 「基于当前知识库，就『<主题>』按『研究问题 / 方法 / 数据集 / 主要结论 / 局限』五列对比以下论文：<论文1>、<论文2>、<论文3>。每条结论后标注论文标题与章节；找不到证据的写"证据不足"，不要补外部知识。」

> **相关工作段**
> 「基于当前知识库的检索结果，写 300 字相关工作综述，每个论断后用 [论文标题 · 章节] 标注证据。只允许使用我提供的检索结果，不要引入范围外文献。」

> **局限与空白**
> 「汇总当前知识库中关于『<主题>』的研究局限与研究空白，按出现频次排序，每条给一句原文依据；同时指出哪些说法只有单篇论文支持。」

> **方法可比性**
> 「比较 A 类方法与 B 类方法在数据集、评价指标、计算成本上的差异，并明确指出哪些对比是可比、哪些不可比，给出判断依据。」

### 6.3 三条写作纪律

1. **先证据后句子**：先在检索里找到证据，再写那句话；反过来最容易写出"看起来很对但没出处"的段落。
2. **未支持结论必须处理**：要么补文献重新生成，要么在正文里降低措辞强度（"可能""在本文语料范围内"）。
3. **数字要能回溯**：论文库导出的 BibTeX 与综述里标注的章节，是你投稿时的核对清单。

## 第 7 步：自证严谨（答辩 / 审稿会被问）

| 想证明 | 入口 | 需要固定什么 |
| --- | --- | --- |
| 检索方案有效 | 知识库详情 → RAG 评估 | 评估基准（问题 + 金标 chunk/答案）+ 模型配置 |
| 哪个环节贡献大 | 知识库详情 → 消融实验 | 固定语料清单（下载后与报告一起归档） |
| 多 Agent 值不值 | 科研罗盘 → 分析对比 | 同一模型、同一论文集，A/B 盲审评分 |
| 好不好用 | 科研罗盘 → 用户评测 | 匿名邀请链接 + 真实参与者填写 |

**判断标准**：没有真实样本时系统只显示"暂无数据"，不会替你下结论——这条边界要在论文与答辩里如实说明。

## 一页速查

```
建库 → 传 PDF → 读论文 → 检索找证据 → 综述（校验→生成→导出）
        ↓                                   ↓
     研究趋势 / 机会                    研究项目（里程碑/任务/成果）
                                            ↓
                                       导出报告 → 论文各章节
                                            ↓
                                   评测 / 消融 / 盲评 / 用户评测
```

## 常见坑（都踩过）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 综述一直失败，提示"只能引用已验证证据" | 检索命中的片段还没录入为证据 | 证据校验面板 →「一键录入并验证」→「重新生成」 |
| 同步引用图谱失败（429） | Semantic Scholar 免费额度限流 | 配 `SEMANTIC_SCHOLAR_API_KEY`；等待后重试 |
| 严格图谱检索报"图谱未就绪" | 还没同步图谱 | 先点「同步引用图谱」 |
| 对话/综述一直"运行中" | worker 没起或模型密钥缺失 | 检查 worker 进程与 `.env` 中模型密钥 |
| 引用图谱页很卡 | 节点过多 | 已在 v0.11.0 关闭布局动画并调参；仍卡时缩小年份范围 |

## 记住三句话

1. **它的价值不是"替你写"，而是"让你写得住"**——每条结论都能指回原文。
2. **顺序不能反**：先证据、再综述、最后动笔。
3. **不确定就去看「未支持结论」和「研究局限」**，那里通常就是审稿人会问的问题。
