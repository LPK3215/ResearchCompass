## 二、当前版本建议的处理优先级

### P0：上线前必须闭环

1. 恢复或切换模型 API。
2. 重新执行论文搜索。
3. 确认真实知识库能返回结果，而不是只返回成功状态。
4. 重新测搜索接口 P95、错误率和并发行为。
5. 补跑 4 个真实模型集成测试。
6. 确认搜索失败时前端能显示清晰原因，而不是只显示“系统错误”。

### P1：商业体验必须加强

1. 增加浏览器端完整写操作回归：
   - 创建研究项目；
   - 创建计划/里程碑/任务；
   - 完成任务；
   - 关联证据或论文；
   - 生成综述；
   - 导出综述；
   - 查看通知。
2. 将外部依赖状态展示给用户：
   - 模型余额不足；
   - 模型超时；
   - 向量库不可用；
   - 知识库仍在处理；
   - 检索可重试。
3. 把检索运行记录做成用户可见的状态：
   - 排队中；
   - 执行中；
   - 成功；
   - 失败可重试；
   - 失败不可重试。
4. 将 Chromium 及其系统依赖写入专用 E2E 镜像或 CI 环境，避免依赖手工安装。

### P2：性能和运维优化

1. 为搜索定义明确指标：
   - 单次搜索最大文件数；
   - 最大 chunks 数；
   - P95/P99 延迟；
   - 并发上限；
   - 外部模型超时；
   - 重试次数。
2. 为 Milvus、模型 API、重排服务增加独立健康检查。
3. 对搜索阶段记录更完整耗时：
   - 查询改写；
   - 向量召回；
   - BM25；
   - 重排；
   - 图谱扩展；
   - 结果聚合。
4. 增加外部 API 熔断、退避重试和限流。
5. 对重复查询增加缓存，减少模型 API 和向量服务压力。
6. 建立正式的压测数据集和固定基线，避免每次使用不同知识库导致结果不可比。

## 最终判断

当前项目已经不是“功能没做完”的状态，而是：

```text
核心科研闭环：已实现
主要业务代码：已通过大量测试
前端关键流程：已通过真实浏览器验证
导出与通知：已实现并验证
任务性能：已达标
论文搜索：代码路径已确认，但被外部模型 API 余额不足阻塞
搜索性能：等待模型 API 恢复后测量
商业体验：还需要加强失败提示、重试体验和完整写操作回归
可扩展能力：项目模板、证据质量、智能综述、协作、可观测性
```

下一步最合理的选择有两个：

1. 先恢复模型 API，我继续把搜索真实结果、搜索性能和 4 个模型集成测试闭环；
2. 暂时不处理外部 API，先推进前端完整写操作回归、错误提示和重试体验。
