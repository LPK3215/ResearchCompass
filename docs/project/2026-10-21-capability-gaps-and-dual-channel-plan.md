- 文档性质：阶段分析 + 修复追踪。**本文档持续编辑**，每个缺口修完在此登记结果与证据，不另开新文档。

- 当前状态：分析完成，待实施
- 关联文档：[能力全景](../intro/capabilities.md)、[从选题到成稿](../intro/research-workflow.md)、[科研罗盘功能说明](../intro/research-compass.md)、[编码规范](../develop-guides/coding-rules.md)

## 1. 结论摘要

1. 系统在"证据链"（导入、检索、取证、综述）上闭环完整；在"发表链"（写作、协作、投稿）上基本空白，对外定位不宜宣传为覆盖八九成学术文献场景。
2. 分析类产出只有"综述、项目报告、引文"三种能落到文件；**单篇论文分析报告不能导出**，也**没有面向组会汇报的产出物**（PPT 不做，HTML 汇报未做）。
3. 人工界面与 AI 工具存在结构性割裂：研究域 **83 个接口对 26 个 AI 工具**，只有 4 个能力域是双通道，其余十余个域仅人工可操作。
4. 架构上补齐成本低（工具与路由共用 service 与权限），缺的是**覆盖面**与**一份可核对的能力矩阵**。

## 2. 产品定位与覆盖度

| 文献工作流阶段 | 现状（已对照代码核对） | 覆盖判断 | 对应缺口 |
| --- | --- | --- | --- |
| 发现 / 导入 | 外部论文检索与导入（Semantic Scholar，仅开放获取）+ 本地 PDF 上传 | 基本覆盖 | G-29（非开放获取全文） |
| 本地预览 | PDF.js 预览 + 证据回原文定位（页码、字符区间） | 覆盖 | 无（用户批注另计，见 G-33） |
| AI 辅助阅读 | 单 Agent 结构化提取 + 四阶段多 Agent + 对话 | 覆盖 | G-12（分析结果不能导出）、G-17/G-18（卡片与分层摘要） |
| 取证 | 本地混合检索、严格图谱检索、证据生命周期 | 覆盖，核心差异点 | 无 |
| 产出 | 证据综述 MD/DOCX、项目报告 MD/Word/CSV、引文 BibTeX/RIS/MD/CSV/txt、用户评测 CSV | 部分覆盖 | G-12、G-19、G-20、G-30、G-31、G-32 |
| 写作 / 协作 / 投稿 | 无 | 空白 | G-26、G-27、G-28 |
| 文献管理生态 | 无 Zotero 同步、无跨库去重；仅支持论文标签 | 空白 | G-24、G-25、G-34 |

对外表述（已采用，见 README 与能力全景）：

> **一个证据可追溯的科研工作台：从文献检索、AI 精读，到带原文出处的证据综述与项目报告。**

"智能分析平台"可作副标题，但需要同时说明边界，避免被理解为"文献数据库 + 写作软件"。

| --- | --- | --- | --- |

| 组会汇报 / 组合汇报 MD | 确认真实缺失：无生成器，只能借道项目报告 | — | G-19（讲稿包）、G-13（HTML 版） |
| 流程图（HTML / 图形） | 确认真实缺失：无专门生成；仅能切通用助手用沙箱手写 HTML | — | G-20（结构化出图）、G-14（copilot 接沙箱） |
| PPT | 明确不做 | 无 | 第 8 节 |
| 文献卡片 / 摘要压缩 | 确认真实缺失：分析页有结构化字段，但无卡片与分层摘要导出 | 对话中让 AI 压缩 | G-17、G-18 |

核对结论（2026-10-21，按路由、service 与导出常量逐项核对）：

- 已具备 4 项：证据综述、项目报告、引文导出（5 种格式）、用户评测 CSV。
- 真实缺失 3 项：单篇分析报告导出、组会/组合汇报、流程图与结构图。
- 部分具备或不做 2 项：文献卡片与分层压缩确实无结构化输出；PPT 维持不做。
- 核对时另发现 5 项此前未记录的数据出口与输入缺口：G-30 引文样式、G-31 评估与统计结果导出、G-32 图谱数据导出、G-33 论文笔记与批注、G-34 整库导出与迁移。

## 4. 双通道现状（人工 UI 与 AI 工具）

统计口径：`backend/server/routers/research_router.py` 共 83 个研究域接口；`backend/package/yuxi/agents/toolkits/research/tools.py` 注册 26 个 `research_*` 工具。

| 能力域 | 人工 UI | AI 工具 | 结论 |
| --- | --- | --- | --- |
| 项目 / 里程碑 / 任务 | 有 | 有 | 双通道 |
| 项目成果归集与计划关联 | 有 | 有 | 双通道 |
| 智能检索（含取回运行结果） | 有 | 有 | 双通道 |
| 证据综述（创建/查询/重生成/导出） | 有 | 有 | 双通道 |
| 项目报告导出 | 有 | 无 | 仅人工（G-02） |
| 论文库导出 | 有 | 无 | 仅人工（G-03） |
| 论文分析（单/多 Agent） | 有 | 无 | 仅人工（G-01） |
| 分析对比（A/B 盲审与汇总） | 有 | 无 | 仅人工（G-09） |
| 引用图谱同步 / 浏览 / 两跳关系 | 有 | 无 | 仅人工（G-05） |
| 趋势 / 机会 | 有 | 无 | 仅人工（G-06） |
| 证据录入 / 验证 / 活动 / 引用 / 影响 | 有 | 无 | 仅人工，导致综述失败只能人工补救（G-04） |
| 风险登记 / 任务依赖 | 有 | 无 | 仅人工（G-07） |
| 用户评测 | 有 | 无 | 仅人工（G-08） |
| 外部论文搜索 / 导入 | 有 | 无 | 仅人工（G-11） |
| RAG 评估 / 基准 / 消融 | 有 | 无 | 仅人工（G-10） |

补充结论：

- 反向不存在"只有 AI 能做"的能力，即 AI 能力集是人工能力集的子集；问题集中在"人工有、AI 没有"。
- research-copilot 的工具集只有 26 个研究工具加 `present_artifacts`，`skills` 为空、无沙箱；通用助手与深度研究才有沙箱执行与 skills（deep-research、image-gen 等）。产出文件类任务被迫切智能体，属能力线不一致（G-14）。

## 6. 修复计划

| 批次 | 内容 | 说明 |
| --- | --- | --- |
| P0 | G-01、G-02、G-03、G-04 | 打通"AI 也能分析、也能交付、也能自救综述"，不带这四项，双通道只是口号 |
| P1 | G-05 至 G-11 | 补齐专业域工具；只读优先，管理类随后 |
| P2 | G-12 至 G-16、G-17 至 G-23、G-30 至 G-32 | 产出物闭环、能力线收敛、矩阵与守卫、对外口径；使用侧新功能（卡片/压缩/汇报包/结构图/对比矩阵/洞察报告/空白转选题）与数据出口（引文样式/评估统计导出/图谱导出） |
| P3 | G-24 至 G-29、G-33 至 G-34 | 生态与写作：需单独立项，先评估外部依赖（Zotero、出版社、查重服务、PDF 批注）再排期 |

实施约定：

1. 每个缺口独立提交，提交信息带缺口编号；工具实现沿用现有 `research_*` 工具风格与 `ToolRuntime` 约定。
2. 工具与路由必须调用同一个 service 与同一套权限校验，禁止在工具里重写业务逻辑。
3. 新增工具后同步更新 `RESEARCH_TOOLS` 注册、智能体提示词中的工具说明、能力矩阵与本文档状态列。
4. 涉及评测与盲评的工具不得替代人工评分；无样本时返回值必须显式为"无数据"。

## 8. 明确不做与边界

| 事项 | 结论 | 理由 |
| --- | --- | --- |
| 生成 PPT | 不做 | 版式与素材约束复杂，投入产出比低；需要时用 HTML 汇报替代 |
| 自动写作整篇论文 | 不做 | 与"可追溯证据"定位冲突，结论必须由作者负责 |
| 无样本时给出优劣结论 | 不做 | 评测与盲评只统计真实人工评分 |
| 图谱缺失时静默降级 | 不做 | 严格图谱模式必须显式失败 |
| 出版社全文下载 | 不做 | 依赖授权与版权，仅支持开放获取 |

## 9. 本文档维护规则

- 每完成一个缺口：更新第 5 节状态与验收证据，并在第 7 节追加一行；不要新建平行文档。
- 新增缺口：在本节上方第 5 节追加 G-xx，按同一格式填写；编号只增不改。
- 结论变化（例如把某项改为"不做"）：在第 8 节登记理由，不删除历史行。
