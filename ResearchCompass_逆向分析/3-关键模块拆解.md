## 模块 1：学术章节分块解析器（AcademicSectionChunker）

**文件**：`backend/package/yuxi/knowledge/chunking/ragflow_like/parsers/academic.py`

**做什么**：把学术论文 PDF/Markdown 解析为带层级语义的 Chunk，而非均匀切段。

**怎么做**（已读源码关键逻辑）：
- `AcademicSectionChunker._chunk_document()`：遍历已识别的章节树（`SectionNode` 层级结构），对每个叶子/子章节调用 `_chunk_section()`
- `_split_section_text()`：当章节文本超过 token 阈值时，按"句子/段落边界"二次切分，避免跨句截断
- `_build_chunk_metadata()`：为每个 Chunk 注入 `section_path`（如 `["1","1.1","1.1.2"]`）、`section_index`、`section_level`、`contains_equations`（公式检测）、以及前后章节上下文 `prev_section_path`/`next_section_path`
- 融合策略 `_merge_small_chunks`：过短 Chunk 向上合并到父章节，保语义完整

**为什么这么做**：RAG 检索质量高度依赖 Chunk 语义边界。普通 `RecursiveCharacterTextSplitter` 会切断公式与章节逻辑，导致 LLM 拿到"残缺上下文"。学术场景必须保留"这是哪一节、是否含公式、上下文是哪节"——这是下游精准检索与证据溯源的前提。

**亮点**：Chunk 自带 `section_path` 元数据，使"按章节聚类综述"（`research_synthesis_service._cluster_by_section`）与"引用溯源"直接可用，零额外计算。

## 模块 2：混合检索服务（ResearchSearchService）

**文件**：`backend/package/yuxi/services/research_search_service.py`

**做什么**：统一的科研检索入口，融合"自有知识库文档 + 自有片段 + 外部学术库（arXiv/ SemanticScholar）"三源，重排后返回。

**怎么做**（已读关键函数）：
- `run_search`（L137）：编排主函数，并发跑三路召回
- `build_doc_retriever`（L242）：组合 `semantic_retriever`（向量）+ `keyword_retriever`（BM25），Ensemble 融合
- `build_chunk_retriever`（L275）：片段级向量召回（更细粒度证据）
- `_search_legacy_papers`（L463）：调外部学术 API（⚠️ 具体 API key 配置未在本次读取范围）
- `_cross_encoder_rerank`（L570）：用 `FlashrankReranker("ms-marco-MiniLM-L-12-v2")` 对合并结果重排，提升 top-k 相关性
- 容错：`try/except` 包裹每路召回，单路失败仅标记 `SearchRun.status=failed`，不阻断其他路

**为什么这么做**：科研证据需要"内部私有文献 + 公开学术库"互补。关键词召回保术语精确（如 "BERT-LSTM"），语义召回保概念扩展（如 "transformer-based encoder"），重排解决混合召回的噪声。

**亮点**：三源异构 → 统一 `SearchRun` 抽象，下游综述/分析只消费一种结构。

## 模块 3：证据综述服务（ResearchSynthesisService）

**文件**：`backend/package/yuxi/services/research_synthesis_service.py`

**做什么**：把检索到的零散证据，聚合成"带来源、可核查"的结构化综述。

**怎么做**（已读关键函数）：
- `run_synthesis`（L127）：主编排，先取 `SearchRun`，再聚类，再流式聚合
- `_cluster_chunks`（L635）：两种策略
  - `_cluster_by_embedding`：embedding + KMeans/HDBSCAN（主题聚类）
  - `_cluster_by_section`：按 Chunk 的 `section_path` 分组（结构聚类，来自模块1的元数据）
- `_stream_synthesize_cluster`（L750）：对每个 cluster 调 LLM 生成综述段落，**流式**回传（前端逐句显示）
- `_verify_synthesis_claims`（L885）：**反幻觉校验**——LLM 把每段综述句与原始 cluster 文本比对，打标 `supported`/`contradicted`/`unverified`，挂回 `source_chunk_ids`

**为什么这么做**：通用 LLM 做综述会"幻觉引用"。本项目把"生成"与"校验"分离，每段话都绑定可点击的证据 Chunk，落实"过程可证明正确"的产品护城河。

**亮点**：`SynthesisChunk` 流式事件（L112）让前端在生成中即可渲染 + 校验态标色，UX 与可信度双赢。

## 模块 4：四阶段论文分析工作流（LangGraph StateGraph）

**文件**：`backend/package/yuxi/services/academic_paper_analysis_workflow.py` + `academic_paper_analysis_service.py`

**做什么**：把单篇论文自动拆解为 结构 / 创新点 / 方法论 / 研究空白 四个维度的结构化分析。

**怎么做**（已读结构）：
- `build_academic_analysis_graph()`：`StateGraph` 注册 4 个节点
  - `structure` → `analyze_structure_node`：抽章节骨架
  - `innovations` → `analyze_innovations_node`：LLM 抽创新点
  - `methodology` → `analyze_methodology_node`：抽方法链
  - `gaps` → `analyze_gaps_node`：推断研究空白/未来方向
  - 另含可选 `analyze_functional_node`（功能分析）
- 边：`START → structure → innovations → methodology → gaps → END`（固定 DAG，可断点续跑）
- `AcademicPaperAnalysisService.run_analysis`：组装 `initial_state`，`graph.ainvoke()` 执行，落 `AnalysisRun` + `AnalysisResult`
- `stream_analysis_progress`：阶段进度流式回传

**为什么这么做**：论文分析是科研核心动作，但人工易遗漏维度、不可复现。固定 DAG 保证"每篇论文走同一把尺子"，结果可横向对比、可重跑。

**亮点**：复用 LangGraph 而非自写状态机——天然支持流式、断点、并行、错误隔离，符合"用框架原语、不重造轮子"的二次开发哲学。

## 模块 5：引用图谱同步服务（AcademicGraphService）

**文件**：`backend/package/yuxi/knowledge/graphs/academic_graph_service.py`

**做什么**：把论文间的引用关系沉淀为可查询的知识图谱，支撑"观点溯源 / 学术脉络"可视化。

**怎么做**（已读关键结构）：
- `sync_document(document_id)`：解析文档引用 → upsert 论文节点 + 引用边
- 双向边建模：`cites`（A→B）与 `cited_by`（B→A）双向维护，查询任一侧都 O(1)
- 冲突处理：节点以 DOI/标题归一化 key 去重，已存在则 merge 属性而非覆盖
- `get_graph_stats`：返回节点数/边数/连通分量，供前端 `getGraphStats` 展示

**为什么这么做**：引用是学术证据链的骨架。图结构比关系表更适合"六度引用追溯""某结论被谁反驳"。双向边避免双向查询时重复遍历。

**亮点**：与 LightRAG 框架图并存但职责分离——LightRAG 管"内容语义图"，本模块管"引用关系图"，互不污染。
