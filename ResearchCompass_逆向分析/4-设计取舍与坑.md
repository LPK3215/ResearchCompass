# 4. 设计取舍与亮点 / 局限与坑

## 4.1 设计亮点（聪明选择）

### 亮点 1：填空式二次开发，零框架侵入
ResearchCompass 不 fork 框架逻辑，只在 3 个扩展槽填空：service（业务）、tool（Agent 入口）、parser（分块）。
唯一接缝是 `run_worker.py` 的 `RESEARCH_COPILOT_AGENT_SLUG` 识别（第 65 行）+ `RESEARCH_CONTEXT_SOURCES` 白名单（第 51 行）。
**好处**：框架升级不影响领域层；领域层可独立测试。这是大型叠层项目能控制复杂度的关键。

### 亮点 2：领域错误 → HTTP 状态码的解耦映射
`research_copilot_service.py` 第 40-52 行定义 `ResearchDomainError`/`ResearchNotFoundError`；`research_router.py` 第 30-56 行 `_handle_domain_error` 统一转 400/404。
service 层完全不 import FastAPI，可在无 Web 上下文下单测。**这是教科书级的契约边界设计。**

### 亮点 3：证据可核查是第一性约束（反幻觉双保险）
- 综述层：`_verify_synthesis_claims`（L885）对每句打标 supported/contradicted/unverified + 挂 `source_chunk_ids`
- 分块层：Chunk 自带 `section_path`，溯源直达章节
- 报告层：`research_project_report_service` 走确定性拼装，**完全不调 LLM**，保证导出可复现
三层共同落实产品护城河"可核查证据 + 可复现 + 数据自托管不出域"。

### 亮点 4：学术分块保留章节语义而非暴力切段
`academic.py` 的 `section_path`/`contains_equations`/`prev_next_section_path` 元数据，让下游聚类、检索、溯源零成本获得结构信息。一次解析，多处复用。

### 亮点 5：流式优先（SSE）
综述（`SynthesisChunk` L112）、分析（`stream_analysis_progress`）、Copilot（`stream_agent_chat`）全链路流式。
UX 上"边生成边看 + 校验态标色"，技术上天然适配长任务（LLM 生成不可预知时长）。

## 4.2 设计取舍（牺牲了什么）

| 取舍 | 得到 | 牺牲 |
|------|------|------|
| 复用 LangGraph 不自写状态机 | 流式/断点/并行免费 | 框架版本耦合（v1 锁定），升级风险 |
| 三源检索融合 | 召回全面 | 延迟叠加（三路并发仍受最慢路拖累）；外部 API 配额/费用 |
| 报告导出绕过 LLM | 可复现/可审计 | 报告文采与洞察深度受限（纯拼装） |
| 引用图与 LightRAG 图分离 | 职责清晰 | 双图维护成本，潜在数据不一致 |
| 信任边界靠 `source` 白名单 | 简单 | 若上游伪造 metadata.source 可绕过（依赖框架鉴权前置） |

## 4.3 局限与坑（含逆向发现的隐患）

### 坑 1：框架↔领域接缝缺乏集成/端到端测试（最高危）
`run_worker.py` 用 `_trusted_research_context()` 注入可信上下文，但本次未读到对该接缝的集成测试。
**风险**：框架层改 `input_metadata` 结构 / `RESEARCH_COPILOT_SOURCE` 重命名，领域层会静默失效（context=None → 退化为普通对话）。
**证据**：`AGENTS.md` 测试规范强调"涉及关键主链路时补跑端到端测试"，但 `research_router.py` 1747 行仅见单元测试引用，未见科研主链路 e2e。

### 坑 2：外部学术库依赖（链路 1 `_search_legacy_papers`）
arXiv / SemanticScholar 有速率限制与字段变更风险。容错仅记 `status=failed`，但前端是否区分"部分失败"与"全失败"未读（⚠️ 待核实前端处理）。

### 坑 3：聚类策略默认选择的黑盒
`_cluster_chunks` 支持 embedding / section 两种，但默认走哪种、KMeans 的 k 如何定（肘部法？固定？）未读（⚠️ 待逐行确认 `run_synthesis` 的 options 默认分支）。

### 坑 4：引用解析健壮性
`academic_graph_service.sync_document` 的引用抽取若依赖正则/GROBID，对扫描件 PDF 或非标准参考文献格式易漏抽（⚠️ 待核实解析实现）。与亮点"可核查"相悖——图谱缺失会误导溯源。

### 坑 5：重排模型固定
`FlashrankReranker("ms-marco-MiniLM-L-12-v2")` 硬编码（链路1）。该模型对中文/跨语言学术检索可能次优，且模型升级需改代码而非配置。

### 坑 6：规模与心智负担
叠层架构（Yuxi L2 + 科研 L3）单轮改动可达 98 文件（`MEMORY.md` 记录），维护者易产生"中间易错"的不确定感——实际风险点收敛在接缝层（坑1），而非地基。需补接缝集成测试消除悬空感。

## 4.4 与商业通用工具的差异定位（产品层）

作者明确：简单版"上传PDF→分析创新点"通用模型已能做，不稀缺。
真正护城河 = **可核查证据 + 可复现 + 数据自托管不出域**。本仓库的工程实现（亮点3三层反幻觉 + 报告确定性拼装）正是该定位的代码落地。
