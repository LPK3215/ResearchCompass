# 1. 架构全景

## 1.1 三层叠层架构（核心发现）

```
┌──────────────────────────────────────────────────────────────────────┐
│  前端层  web/ (Vue3 + TS)                                              │
│  views/research/  ·  apis/research_api.js                              │
│  对话优先的科研智能体界面 + Agent 执行流程检视器                         │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │  HTTP / SSE 流式
┌───────────────────────────────┴──────────────────────────────────────┐
│  暴露层（L3 边界）                                                     │
│  backend/server/routers/research_router.py  ← 全部科研 REST 契约        │
│  backend/package/yuxi/services/run_worker.py ← Agent 运行态接缝          │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │  调用
┌───────────────────────────────┴──────────────────────────────────────┐
│  科研业务 service 层（L3 领域逻辑，纯函数/服务，无框架耦合）            │
│  research_copilot_service · research_search_service                    │
│  research_synthesis_service · research_project_report_service          │
│  academic_paper_analysis_workflow/service · academic_graph_service     │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │  组合 / 注册
┌───────────────────────────────┴──────────────────────────────────────┐
│  领域工具 + 解析器（L3 填空）                                          │
│  toolkits/research/tools.py (27+ @tool)                                │
│  chunking/ragflow_like/parsers/academic.py (学术章节分块)              │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │  依赖（不重写，只复用）
┌───────────────────────────────┴──────────────────────────────────────┐
│  框架地基 Yuxi（L2 原语，作者不改动）                                  │
│  LangGraph 运行态 · FastAPI · PostgreSQL · Redis/ARQ · LightRAG 图     │
│  向量库 · 沙盒 sandbox · 中间件 middleware · 鉴权 auth · 审计 audit    │
│  知识库 CRUD · 技能 skill · 工具注册 registry · 对话 chat              │
└──────────────────────────────────────────────────────────────────────┘
```

**设计意图（已读 `AGENTS.md` + `ARCHITECTURE.md` 印证）**：
ResearchCompass 的本质是"在 Yuxi 的对话页底层，把后端替换为科研业务 agent，注册科研工具/技能，外科手术式替换，不重写对话/管理页"。
三层职责：①对话页=留表面换底层；②工作台=降级为"agent 执行流程与结果的检视器"；③技能/工具/智能体管理=框架原生 UI 原样保留。

## 1.2 模块依赖关系（调用方向，已读源码确认）

```
research_router.py
   ├─> research_copilot_service.py     (编排 ResearchCopilot 运行)
   ├─> research_search_service.py      (混合检索 + 重排)
   ├─> research_synthesis_service.py   (证据综述)
   ├─> academic_paper_analysis_workflow.py + academic_paper_analysis_service.py (四阶段论文分析)
   ├─> academic_graph_service.py       (引用图谱双向同步)
   ├─> research_project_report_service.py (报告确定性拼装导出)
   └─> run_worker.py ──(识别 RESEARCH_COPILOT_AGENT_SLUG)──> 框架 LangGraph 运行态

tools.py (@tool)
   └─> 上述 service 层（工具是 service 的 Agent 友好入口）
```

## 1.3 核心抽象（从代码反推）

1. **`RESEARCH_COPILOT_AGENT_SLUG`**（常量，`agent_repository`）
   框架识别"科研 Copilot agent"的唯一标识。`run_worker.py` 第 65 行 `if agent_slug != RESEARCH_COPILOT_AGENT_SLUG` 是领域层与框架运行态的唯一接缝开关。

2. **`RESEARCH_COPILOT_SOURCE` / `RESEARCH_CONTEXT_SOURCES`**（`run_worker.py` 第 51 行）
   白名单集合 `{RESEARCH_COPILOT_SOURCE, "ask_user_question_resume"}`。`_trusted_research_context()` 校验 `input_metadata.get("source")` 必须在白名单内，才注入可信 `research_context`（用于断点续跑 / 追问）。这是"框架↔领域"的信任边界。

3. **`ResearchDomainError` / `ResearchNotFoundError`**（`research_copilot_service.py` 第 40-52 行）
   领域层自定义错误类型 → 映射到 HTTP 状态码：`ResearchNotFoundError→404`，`ResearchDomainError→400`。`research_router.py` 第 30-56 行 `async def _handle_domain_error` 统一捕获。**亮点**：领域错误与 HTTP 契约解耦，service 层不依赖 FastAPI。

4. **`Chunk` / `Document`**（`academic.py` 解析器输出）
   学术分块的标准数据结构，携带 `section_path`（层级路径）、`section_index`、`section_level`、`contains_equations`。下游检索/摘要/RAG 均消费此结构。

5. **`SearchRun` / `SynthesisRun` / `AnalysisRun` / `EvaluationExperiment`**（`tools.py` 第 21 行 `AssetType`）
   科研资产的统一类型枚举，贯穿检索→综述→分析→评测全生命周期。

## 1.4 前端科研视图（已读 `research_api.js` 与 `views/research/`）

前端按"对话优先 + 工作台检视"双层呈现：
- `apis/research_api.js`：`listResearchProjects`、`getResearchProject`、`chatWithResearchCopilot`、`searchAcademicPapers`、`synthesizeEvidence`、`getSynthesisResult`、`startPaperAnalysis`、`getGraphStats` 等——与 `research_router.py` 路由一一对应。
- `views/research/` 子目录（202 文件中的科研视图）：对话页、证据综述页、论文分析页、引用图谱可视化、项目治理页。

## 1.5 部署拓扑（`docker-compose.yml` 已读）

- `api`（容器 `api-dev`）：FastAPI + 热重载
- `web`（容器 `web-dev`）：Vue 前端 + 热重载
- `postgres`：业务数据 + 图谱节点/关系（疑似 pgvector）
- `redis`：ARQ 队列 + 缓存 + 取消信号（`run_worker.py` 用 `has_cancel_signal`）
- `lightrag`：知识图谱服务
- `arq worker`：`run_worker.py` 的异步执行容器

> ⚠️ 待核实：图谱后端在代码层标注为"Neo4j / Postgres 双向同步"（`academic_graph_service.py`），但 `docker-compose.yml` 中未显见独立 Neo4j 服务，推断由 Postgres 承载（pg 同时存业务与图），或 Neo4j 为可选外部依赖。需核对 `docker-compose.yml` 全量确认。
