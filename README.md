<h1>ResearchCompass</h1>

<p><strong>ResearchCompass is an evidence-traceable research workspace for literature review, evidence synthesis, and project execution.</strong></p>

<p>It turns papers into a searchable, auditable private library, then connects evidence search, paper reading, evidence-bound synthesis, research projects, and report export into one traceable pipeline. Built on the open-source Yuxi agent framework, it adds academic section chunking, citation graphs, evidence validation, and reproducible evaluation.</p>

## What it does

| You want to… | What you actually get | Where |
| --- | --- | --- |
| Build a private literature library | Papers chunked by academic sections (Abstract / Method / Experiments…), with page numbers and character ranges | Knowledge → Knowledge base |
| Find traceable evidence | Paper + section + original passage + four retrieval scores, openable at the exact PDF location | Research Compass → Smart search |
| Write an evidence-bound review | Topic synthesis, key claims, contradictions, limitations, gaps — plus an explicit "unsupported claims" list | Research Compass → Evidence synthesis |
| Understand a single paper | One-pass structured extraction, or a four-stage multi-agent breakdown (innovations / methodology / gaps) | Paper library → Paper analysis |
| Run a real research project | Milestones, tasks, asset links, risks, deterministic progress and exportable reports | Research Compass → Research projects |
| See the research landscape | Citation graph with two-hop relations, publication trends, opportunity scores with reasons | Research Compass → Graph / Trends / Opportunities |
| Use the AI research assistant | A conversational assistant that carries the active knowledge base, project and selected object into each run, calls permission-checked domain tools, and asks for approval before sensitive changes | Research Compass right panel / Research assistant page |
| Prove it works | RAG evaluation, retrieval ablations, single-vs-multi-agent blind review, anonymous SUS studies | Knowledge base detail / Research Compass → Analysis comparison, User studies |

Under the hood, the open-source Yuxi base provides the multi-tenant knowledge base, LangGraph agent runtime, sandbox, middleware, MCP/Skills/SubAgents and model-provider configuration. ResearchCompass adds academic section chunking, citation graphs, evidence-constrained synthesis, project execution and reproducible evaluation on top of that base.

## End-to-end workflow

```text
Build library → Upload PDFs → Read papers → Search evidence → Synthesis (validate → generate → export)
        ↓                                      ↓
   Trends / opportunities                 Research project (milestones / tasks / assets)
                                               ↓
                                       Export report → manuscript sections
                                               ↓
                                  Evaluation / ablation / blind review / user study
```

- [From topic to draft](docs/intro/research-workflow.md) explains every step, its output and how to tell it worked.
- [Capabilities overview](docs/intro/capabilities.md) is the short "what can it do" tour.

## Quick start (30 minutes)

1. Create a Milvus knowledge base, upload 5–10 papers you already know, and choose the **Academic Paper** chunking strategy.
2. Open **Smart search**, ask a question whose answer you know, and check that the returned evidence matches the original PDF.
3. Generate a small **Evidence synthesis**. If evidence validation fails, use **Ingest and verify** and regenerate.
4. Create a **Research project**, collect the search and synthesis results, and export a Markdown report.

## Install and run

### Prerequisites

- Docker Engine and Docker Compose.
- At least one OpenAI-compatible chat model and one embedding model. The full stack also ships a local `local-embedding` provider.
- Python 3.12–3.13 and pnpm 10.11.0 only if you run the backend or frontend outside Docker.

### Development

```bash
git clone --branch v0.11.15 --depth 1 https://github.com/LPK3215/ResearchCompass.git
cd ResearchCompass

# Linux / macOS
./scripts/init.sh

# Windows PowerShell
.\scripts\init.ps1

docker compose up -d --build
```

- Web: <http://localhost:5173>
- API health: <http://localhost:5051/api/system/health>
- API docs: <http://localhost:5051/docs>

The full stack starts PostgreSQL, Redis, MinIO, Milvus, Neo4j, the API, the worker and the web app. MinerU and PaddleX are in the `all` profile and can be started when needed.

### Lite mode

If you do not need knowledge bases, graphs or research dependencies:

```bash
make up-lite
```

Lite mode starts the core services only, defaults to `/agent`, and hides the ResearchCompass, knowledge-base and graph entries. Run `make up` to return to the full stack.

### Production deployment

```bash
cp .env.prod.template .env.prod
# Fill in every REQUIRED value and the real model credentials
docker compose -f docker-compose.prod.yml config --quiet
docker compose -f docker-compose.prod.yml up -d --build
```

Never commit `.env`, `.env.prod`, test accounts, private papers or API keys. See [Production deployment](docs/advanced/deployment.md) for details.

### Verification

For a full cold-build check on Windows:

```powershell
.\scripts\release_check.ps1
```

For local checks:

```bash
make lint
make test
make test-web
make docs-build
```

`release_check.ps1` cold-builds the development and production images (full and Lite frontends), checks both Python lock files and the full Ruff rule set, runs backend unit/integration/e2e tests, and runs frontend unit tests, ESLint, the production build and the VitePress documentation build.

## FAQ

- **Why does synthesis fail with "only verified evidence"?** Verify the retrieved chunks in the evidence panel and regenerate. The system will not turn unverified text into a supported claim.
- **Why does strict graph search fail?** Sync the citation graph first; strict mode does not silently fall back.
- **Why are the manifests at 0.11.0 while the tag is v0.11.15?** The manifests are package metadata; the tag is the release. See [CHANGELOG.md](CHANGELOG.md).

More questions and fixes: [FAQ.md](FAQ.md).

## Security

Please report vulnerabilities privately through [SECURITY.md](SECURITY.md) or GitHub Security Advisories. Do not open a public issue for a security problem. The AI research assistant does not execute shell commands or write arbitrary files; research deliverables are produced through export tools. Other agents that need sandbox execution use the dedicated sandbox service.
